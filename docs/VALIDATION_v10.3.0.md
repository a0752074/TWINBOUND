## Regression and scoring

- All equipment prices, masses, resource values, multipliers, Combo and original award formulas retain their original regression checks.
- Exact comparisons against the untouched v10.2 Flight fixture cover all destinations, multiple seeds and all equipment tiers in 2D. An original-lane 3D comparison retains baseline awards and encounters.
- High positive/negative altitude tests reproduce the original global-plane offset and check fixed-height spawning, RNG stability, immutable contact positions, repeated view changes, edge cues and actual draw commands.
- Existing 3D tests preserve thrust normalization, opposite-axis cancellation, momentum, real normal-axis trajectory changes, fuel spending and swept spatial collisions.
- New score vectors cover compatible/incompatible instruments, half data, in-transit-only data, storage loss, no observations, fuel exhaustion, low battery history, cheap/expensive designs, budget-invariant cost reference, Proxima archives, partial failure/abort credit, repeated calculations and mode-switch non-farming.
- App-flow tests run the actual planning and trade Workers and cover login validation, configuration feedback, science estimates, both views, flight-time player-switch protection, pause/end/save, report reopening, two-player isolation, return to a prior profile, all four launches and offline API/source-metadata failure.

The application-flow adapter is not a real browser: it has no layout engine, real IndexedDB, browser security/CORS enforcement, GPU performance, mobile touch hardware or audio output. Its persistence tests exercise the localStorage fallback; IndexedDB uses the platform's standard transactional API but was not exercised by Chromium here. Renderer previews record the actual Canvas commands and do not prove the full HTML/CSS layout.

## API and database

Six genuine controlled records are generated for the integration suite: two Moon aborts including a 3D interval, and complete controlled Moon/Mars/Pluto/Proxima flights. Controlled fixtures disable random encounters to isolate mission/score/API consistency; the separate 36-flight balance sweep retains real random encounters.

Live HTTP tests verify canonical IDs, distinct players, all-destination score acceptance, one best per player, stable ties, full detail reads, repeated concurrent UUID submission, conflict rejection, restart persistence, invalid score versions, negative/NaN/oversized values, altered ledgers, inconsistent science data, CORS allowlisting, duplicate JSON fields, pagination bounds and normal static assets. Concurrent store tests add 160 player records plus 55 history records and verify page/rank counts. Rate-limiter behavior is tested separately.

These are reasonable input/composition protections for a public-nickname game. They are not authentication or proof that an untrusted browser actually flew the submitted mission. No formal anti-cheat claim is made.

## Reproduce

```sh
npm test
python -m unittest discover -s tests -p test_server.py -v
node tools/export_score_rules.mjs --check
python tools/verify_release.py
node tools/render_visibility.mjs
node tools/calibrate_mission_score.mjs
```

The calibration command is optional and slower; it regenerates measurement evidence, not the fixed runtime caps. The full application can be played without Node.js or any NASA/network dependency after extraction and Python startup.
